設定を書き換える場所は2つだけ。

| 場所 | 中身 |
|---|---|
| リポジトリの `config.json` | 公開URL、リポジトリ名、フォームのURLと項目番号、アクセス解析 |
| Apps Scriptの「スクリプト プロパティ」 | GitHubのトークン、リポジトリ名、公開URL |

## 1. GitHub

1. 組織 `goshuin-map` を作る（無料プラン）。**People → 自分 → Organization visibility を Private** にする。
2. 組織にリポジトリ `goshuin-map.github.io` を **Public** で作る（中身は空でよい）。
3. このフォルダの中身を push する。gitのユーザー名はニックネームにする。
   ```bash
   git init -b main
   ```
   ```bash
   git config user.name "ニックネーム"
   ```
   ```bash
   git config user.email "ニックネーム@users.noreply.github.com"
   ```
   ```bash
   git add -A
   ```
   ```bash
   git commit -m "最初の公開"
   ```
   ```bash
   git remote add origin https://github.com/goshuin-map/goshuin-map.github.io.git
   ```
   ```bash
   git push -u origin main
   ```
4. リポジトリの **Settings → Pages**：Source を「Deploy from a branch」、Branch を `main` / `/(root)` にする。
5. **Settings → Actions → General → Workflow permissions** を「Read and write permissions」にする。
6. 数分後、`https://goshuin-map.github.io/` が開くことを確かめる。

> GitHubのユーザー名は、コミットやActionsの実行記録に表示される。ユーザー名から本人が分かる場合は、運営専用のGitHubアカウントを作ってから組織を作る（設計書 §10-3）。

## 2. OSMデータの最初の取得

1. リポジトリの **Actions → 「OSMデータの更新」→ Run workflow** を押す（入力欄は空のまま）。
2. 全国で30分〜1時間ほどかかる。Overpass APIが混んでいると一部の都道府県が失敗することがある。その場合は、失敗した都道府県のコードを入力欄に入れてもう一度実行する（例：`13,27`）。
3. 終わると `data/shrines/01.json`〜`47.json` が更新される。以後は毎月2日の午前3時（日本時間）に自動で動く。

## 3. 投稿フォーム（Googleフォーム）

運営専用のGoogleアカウントで作る。

### 3.1 フォームを作る

タイトル：`みんなの御朱印マップ 投稿フォーム`

説明文（例）：

> 神社の御朱印の情報を投稿するフォームです。投稿の前に利用規約（https://goshuin-map.github.io/terms.html）をお読みください。
> 投稿は運営者が確認してから掲載します。**掲載の可否や結果のお知らせはしません。**

質問は次の順番で作る。**質問名は一字一句このとおりにする**（Apps Scriptが質問名でデータを読むため）。

| # | 質問名 | 種類 | 必須 | 設定 |
|---|---|---|---|---|
| 1 | `投稿の種類` | ラジオボタン | ○ | 選択肢：`新しい情報` ／ `修正の報告` |
| 2 | `神社名` | 記述式（短文） | ○ | |
| 3 | `御朱印の状態` | ラジオボタン | ○ | 選択肢：`直書きあり` ／ `書き置きのみ` ／ `御朱印なし`。説明：「別の神社で授与している場合や、不定期の場合も、もらえるなら直書き・書き置きのどちらかを選んでください」 |
| 4 | `授与場所` | 記述式（短文） | | 説明：「この神社以外で授与している場合のみ（例：〇〇神社の社務所）」 |
| 5 | `初穂料` | 記述式（短文） | | |
| 6 | `受付時間` | 記述式（短文） | | 説明：「不定期の場合は条件も（例：土日のみ、例大祭の日のみ）」 |
| 7 | `限定・季節の御朱印` | 段落 | | |
| 8 | `御朱印帳の授与` | ラジオボタン | | 選択肢：`あり` ／ `なし` ／ `分からない` |
| 9 | `写真1` | ファイルのアップロード | | 「特定のファイル形式のみ許可」→ 画像。ファイルの最大数 1、最大サイズ 10MB |
| 10 | `写真2` | 同上 | | 同上 |
| 11 | `写真3` | 同上 | | 同上 |
| 12 | `コメント` | 段落 | | 説明：「御朱印が複数ある場合の説明など」 |
| 13 | `投稿者名の表示` | ラジオボタン | ○ | 選択肢：`ニックネームを表示` ／ `匿名` |
| 14 | `ニックネーム` | 記述式（短文） | | |
| 15 | `参拝日` | 日付 | ○ | 説明：「この日を最終確認日として表示します」 |
| 16 | `利用規約への同意` | チェックボックス | ○ | 選択肢：`利用規約に同意します` |
| — | （セクションを追加）`システム用（変更しないでください）` | | | 説明：「自動で入力されています。そのまま送信してください」 |
| 17 | `神社ID` | 記述式（短文） | | |
| 18 | `緯度` | 記述式（短文） | ○ | |
| 19 | `経度` | 記述式（短文） | ○ | |
| 20 | `都道府県コード` | 記述式（短文） | ○ | |

写真の説明には「ご自身で撮影した写真だけを投稿してください。人の顔や車のナンバーが写らないようにしてください」と書く。

写真の項目が3つに分かれているのは、Googleフォームでは枚数の上限を「1・5・10」からしか選べないため。

### 3.2 フォームの設定

- **設定 → 回答**：「メールアドレスを収集する」は「確認済み」（ファイルのアップロードがあるとログインが必須になる）。
- **回答タブ → ︙ → 新しい回答についてのメール通知を受け取る** をオンにする（F-55）。
- **回答タブ → スプレッドシートにリンク** で、新しいスプレッドシートを作る（名前の例：`御朱印マップ 管理`）。

### 3.3 事前入力の項目番号を調べて `config.json` に書く

1. フォームの編集画面で **︙ → 事前入力したURLを取得**。
2. 次の6項目に、目印になる値を入れる：投稿の種類＝`新しい情報`、神社名＝`NAME`、神社ID＝`ID`、緯度＝`LAT`、経度＝`LON`、都道府県コード＝`PREF`。
3. 「リンクを取得」→ コピーすると、次のようなURLになる。
   `https://docs.google.com/forms/d/e/1FAIpQL…/viewform?usp=pp_url&entry.111=新しい情報&entry.222=NAME&entry.333=ID&…`
4. `config.json` の `form.post` に書き写す。
   ```json
   "post": {
     "url": "https://docs.google.com/forms/d/e/1FAIpQL…/viewform",
     "entries": {
       "kind": "entry.111",
       "name": "entry.222",
       "id": "entry.333",
       "lat": "entry.444",
       "lon": "entry.555",
       "pref": "entry.666"
     }
   }
   ```
   `url` は `?` より前まで。`entry.数字` は、目印の値（`NAME` など）の直前にあるもの。
5. push して、サイトの「この神社の情報を投稿する」を押し、神社名などが入力済みのフォームが開くことを確かめる。

## 4. スプレッドシートとApps Script

### 4.1 GitHubのトークンを作る

1. GitHubの **Settings（個人）→ Developer settings → Personal access tokens → Fine-grained tokens → Generate new token**。
2. Resource owner：`goshuin-map`、Repository access：**Only select repositories** → `goshuin-map.github.io`。
3. Permissions：**Repository permissions → Contents：Read and write** だけ。
4. 有効期限は最長（1年）。**期限の日をカレンダーに入れておく**（切れると承認がエラーになる）。
5. 表示されたトークンをコピーする（この画面でしか見られない）。

組織の設定で fine-grained トークンが許可されていない場合は、組織の **Settings → Personal access tokens** で許可する。

### 4.2 Apps Scriptを入れる

1. 3.2で作ったスプレッドシートを開き、**拡張機能 → Apps Script**。
2. 最初からある `コード.gs` の中身をすべて消し、このリポジトリの `gas/Code.gs` の中身を貼り付けて保存する。
3. 左の **⚙ プロジェクトの設定 → スクリプト プロパティ** に3つ追加する。

   | プロパティ | 値 |
   |---|---|
   | `GITHUB_TOKEN` | 4.1のトークン |
   | `GITHUB_REPO` | `goshuin-map/goshuin-map.github.io` |
   | `SITE_URL` | `https://goshuin-map.github.io/` |

4. エディタに戻り、上の関数の選択で `setup` を選んで **実行**。権限の確認が出るので許可する（「このアプリは確認されていません」と出たら「詳細 → 移動」）。
5. スプレッドシートに「承認」「一括登録」「掲載しない神社」「ログ」のシートができる。Googleドライブに「御朱印マップ_一括登録の写真」フォルダができる。

### 4.3 承認のしかた

| したいこと | 操作 |
|---|---|
| 投稿を掲載する | 「承認」シートで、その行の **承認** にチェック |
| 投稿を掲載しない | その行の **却下** にチェック |
| 神社の掲載をやめる | 「掲載しない神社」シートに 神社ID を書き、操作＝`掲載停止` を選んで **実行** にチェック |
| 投稿者からの削除依頼 | 同じシートで、操作＝`削除のみ` |

- チェックすると「状態」が「送信中…」→「送信済み」になる。数分後にサイトへ反映される。
- 「エラー」になったら「メモ」列に理由が出る。直してもう一度チェックすればやり直せる。
- スマホの「Googleスプレッドシート」アプリからも同じ操作ができる。
- 神社IDは、サイトの詳細画面の一番下に表示されている（`n123…` など）。

## 5. 通しの確認

公開前に、必ず一度ためす。

1. サイトで適当な神社を開き、「この神社の情報を投稿する」からテスト投稿をする。**位置情報を付けて撮ったスマホの写真**を1枚付ける。
2. 運営用Gmailに通知が届く。「承認」シートに行が増え、写真が表示される。
3. **承認** にチェック → 「送信済み」になる。
4. GitHubの **Actions →「投稿の反映」** が動いて成功することを確かめる。
5. サイトを再読み込みし、ピンの色が変わり、詳細に写真が出ることを確かめる。
6. **写真の位置情報が消えていることを確かめる**（重要）。
   - サイトの写真を保存し、パソコンでファイルの「プロパティ → 詳細」（Macは「情報を見る」）を開いて、GPS・撮影場所・カメラの機種が**ない**ことを確かめる。
   - リポジトリの履歴も確かめる：**Commits → 「（投稿ID） 写真1」のコミット** を開き、そこに置かれた画像（`inbox/…/1.jpg`）も同じように保存して確かめる。
   - もし位置情報が残っていたら、公開せずに開発者へ連絡する（設計書 §10-1。中継用の非公開リポジトリを挟む方式に変える）。
7. テスト投稿を消す：「掲載しない神社」シートで、その神社IDを 操作＝`削除のみ` で実行する。

## 6. お問い合わせフォーム・アクセス解析

### お問い合わせフォーム（F-98）

もう1つGoogleフォームを作る（ファイルのアップロードは付けない。ログイン不要になる）。

| 質問名 | 種類 | 必須 |
|---|---|---|
| お問い合わせの種類 | ラジオ：お問い合わせ ／ 投稿の削除依頼 ／ 神社からの掲載停止の依頼 ／ その他 | ○ |
| 内容 | 段落 | ○ |
| 対象の神社名 | 記述式 | |
| 返信が必要な場合の連絡先 | 記述式 | |

フォームの公開用URL（「送信 → リンク」）を `config.json` の `form.contact.url` に書く。メール通知もオンにする。

### GoatCounter（F-99）

登録したコード（`https://コード.goatcounter.com` の「コード」の部分）を `config.json` の `analytics.goatcounter` に書く。空のままなら解析は動かない。

## 7. 最初のデータの一括登録

1. 写真を、Googleドライブの「御朱印マップ_一括登録の写真」フォルダに入れる。ファイル名は重ならないようにする（例：`meiji-1.jpg`）。
2. サイトで登録したい神社を開き、詳細の一番下の **「IDをコピー」** を押す。
3. 「一括登録」シートの **神社ID** のセルを選んで貼り付ける。神社ID・神社名・緯度・経度・都道府県の5列がまとめて入る。
4. 御朱印の状態、初穂料、参拝日など残りの列を入力する。写真1〜3にはファイル名を書く。投稿者名は空なら「匿名」になる。
5. **承認** にチェックする。1行ずつ、「送信済み」になってから次の行にチェックする。

OSMにない神社は、神社IDを空にして、神社名・緯度・経度・都道府県コード（`13` など2桁）を手で入力する。

## 8. 公開後の運用

| いつ | すること |
|---|---|
| 投稿の通知が来たら | 「承認」シートで承認または却下 |
| 月に1回くらい | GitHubのActionsに失敗（赤い×）がないか見る |
| 年に1回 | GitHubのトークンを作り直し、スクリプト プロパティの `GITHUB_TOKEN` を入れ替える |
| 公開日 | `terms.html` と `privacy.html` の「制定日」を書き換える |

### 削除した写真を履歴からも消したいとき

サイトから削除した写真も、リポジトリの過去の履歴には残る。強い削除依頼があった場合は、履歴を書き換えて消す（`git filter-repo --path data/photos/<神社ID> --invert-paths` のあと強制push）。作業の前に必ずバックアップを取り、開発者に相談する。

## 9. 別の組織へ移すとき

1. 移行先の組織にリポジトリ（例：`<組織名>/goshuin-map`）をコピーし、Pagesを有効にする。
2. `config.json` の `site.url` と `repo` を新しい値にする。
3. GitHubのトークンを新しいリポジトリ用に作り直し、スクリプト プロパティの `GITHUB_TOKEN`・`GITHUB_REPO`・`SITE_URL` を書き換える。
4. フォームの説明文、Instagramなどに書いたURLを書き換える。
5. 元の `goshuin-map.github.io` は削除せず、`index.html` を新しいURLへ自動で移動するページに置き換える。

サイトの中のリンクはすべて相対パスなので、プログラムの書き換えは要らない。
